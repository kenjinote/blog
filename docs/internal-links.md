# キーワードから記事への内部リンクを追加する

Python 3.10以上と、このブログをビルドできる Hugo が必要です。外部Pythonライブラリは不要です。
従来の `linkizer*.py` と併用せず、こちらを使用してください。

## 実行方法

リポジトリ直下で実行します。

```powershell
# 新規記事・翻訳を含め、全公開記事から用語辞書を再生成
python scripts/extract_internal_link_terms.py

# 差分と件数を確認（ファイルは変更しない）
python scripts/internal_links.py --localize-existing

# 確認した変更を記事に反映
python scripts/internal_links.py --localize-existing --write --quiet --report docs/internal-links-run-report.json

# 再実行時に変更予定が0件になることを確認
python scripts/internal_links.py --localize-existing --quiet

# 保護処理のテストとサイトのビルド
python -m unittest discover -s scripts -p test_internal_links.py -v
hugo --renderToMemory
```

公開・デプロイは行いません。実行前にGitで現在の編集状態を確認し、実行後は差分をレビューしてください。
本文の変更を戻す場合は、他の編集を消さないよう今回追加したリンクだけを取り消してください。

## 設定を追加する

自動抽出辞書は `scripts/internal-links.generated.json` です。全公開記事の各言語タイトル、説明部分の前にある主題、括弧内の別名、主題にも含まれる冒頭の強調用語から候補を作ります。手順を説明する記事は道具名を一般的な用語として登録せず、タイトル全体を採用します。広すぎる分野名・3文字未満の候補・複数記事で重複する用語は自動採用しません。各記事に本文中の一致箇所があるとは限らず、辞書に登録されてもリンク追加数が0になる記事があります。

抽出結果・言語別件数・曖昧で除外した用語は `docs/internal-links-extraction-report.json` に記録します。自動抽出は文脈の意味を推論する処理ではないため、抽出辞書は編集可能にしています。

`scripts/internal-links.json` の `articles` に、記事ファイルと表記ゆれを含むキーワードを登録します。
こちらは手動設定で、自動抽出辞書より優先されます。再抽出しても手動設定は保持されます。標準実行では両方の辞書を読み込みます。自動抽出辞書を直接直した内容は再抽出で更新されるので、継続的な調整は手動設定で行ってください。

```json
{
  "version": 1,
  "articles": [
    {
      "article": "content/post/goldbachs-conjecture/index.md",
      "keywords": ["ゴールドバッハの予想", "ゴールドバッハ予想"]
    }
  ]
}
```

記事のパスはリポジトリからの相対パスです。URLは `hugo list published` の結果から取得するため、slug・言語プレフィックス・permalink設定が反映されます。サイト内のルート相対リンクを生成します。
公開対象に存在しない記事、下書き・未来の公開予定記事などへの設定はエラーとし、書き込み前に停止します。

`index.md` は日本語、`index.en.md` は英語というこのブログの命名規則を使用します。
英語を追加するときは英語版の記事ファイルと英語のキーワードを別エントリーに登録してください。同じ言語の記事だけが対象で、自分自身へのリンクは作りません。処理元もHugoの公開対象記事に限定します。

手動キーワードは2文字以上の通常の文言で、通常は大文字・小文字を区別せず一致します。ただし3～8文字の英大文字・数字からなる略語（FFTなど）は大文字・小文字を区別し、一般語への誤一致を防ぎます。本文の表記はそのまま保持します。同じ辞書・言語でキーワードが重複するとエラーになります。長いキーワードを優先します。欧文・キリル文字・アラビア文字などでは単語の途中を避け、日本語・中国語・韓国語では助詞などの隣接を許容します。
別の設定ファイルも指定できます。

```powershell
python scripts/internal_links.py --config scripts/another-links.json
```

## 既存リンクの言語修正

`--localize-existing` を指定すると、既存の通常のMarkdownリンクが別言語の記事を指している場合に、同じ記事フォルダー内の公開済み翻訳へURLだけを修正します。翻訳先のslugが異なっていてもHugoの実際のURLを使用します。翻訳先がなければ元のURLを維持し、存在しないページを作りません。

リンクラベル・タイトル属性・クエリ・フラグメントは維持します。フラグメントに対応する見出し名の翻訳は行いません。外部サイト・画像・数式・コード内は対象外です。保護対象記事や参照定義など、保守的に処理できない構文は変更しません。

`--report` には全スキャン件数、言語別の変更記事数・追加リンク数・既存リンク言語修正数・記事全体を保護した件数と、変更記事・保護記事の一覧が保存されます。`--quiet` はdiff表示だけを抑制します。

## 表示を保護する方針と制限

Markdown全体を再生成せず、元の文字列の安全な箇所にだけリンク記法を挿入します。改行コード・BOM・フロントマターを保持し、変更後の再実行で結果が変わらないことを全ファイルの書き込み前に検証します。

- 既存リンク・画像・参照リンク・参照定義、コードフェンス（バッククォート／チルダ、Mermaidを含む）、インラインコードを保護します。
- `$...$`、`$$...$$`、`\(...\)`、`\[...\]` の数式を保護します。
- 見出し、インデント付きコード、引用、属性記法を含む段落にはリンクを追加しません。既存リンクの言語修正では、見出し・引用中のURLも修正できます。
- HTMLタグ・HTMLコメントまたはHugoショートコードを含む記事は、複数段落にまたがる独自構文を壊さないため記事全体を対象外にします。
- フロントマターがない／閉じていない記事は対象外です。コード・数式・リンクの閉じが見つからない場合も、残りを保護するなど保守的に処理します。

安全性を優先した専用スキャナーで、あらゆるMarkdown拡張を解釈する汎用パーサーではありません。複雑な構文ではリンクを追加しない場合があります。対象外の箇所は手動で編集してください。安全に処理できる本文中では、同じキーワードの複数出現もリンク化します。
設定の削除による既存リンクの除去や別の記事への付け替えは行いません。`--localize-existing` による同一記事の言語修正以外は別途編集してください。
