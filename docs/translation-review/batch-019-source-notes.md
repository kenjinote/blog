## 実際に再現した旧コードの問題

- `printPrimes(0)`、`printPrimes(1)`、`printPrimes(-1)` がいずれも `2` を出力する。
- 32ビットintの `isPrime(INT_MAX)` は `46343 * 46343` で符号付き整数オーバーフロー。WSL Ubuntu GCC13.3、C17、O0、UBSanで検出。
- 旧printerの最終加算 `INT_MAX + 2` もUBSanで検出。ただしその加算だけを独立に再現したものであり、INT_MAXまでの全列挙を実行したのではない。
- `scanf` の失敗時に代入されないことを、初期値12345の検査用変数と `abc` 入力で確認。元コードの未初期化変数利用リスクは本文を読んだ判断であり、未初期化メモリ検出器を使ったという主張ではない。
- 「6の倍数」の説明は候補 `6k - 1` / `6k + 1` と不一致。英語・簡体字の旧「刻み幅6」はそれ自体誤りではないが、何を調べるか補った。

## 一次資料の限定読了

[WG14 C11委員会草案 N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf) の該当箇所を読んだ。701ページ全体や最終C17規格の読了とはしていない。

- 6.5 paragraph5：式の結果が型の表現範囲にない場合の未定義動作。
- 7.4 paragraph1：文字分類関数の引数はunsigned charで表現可能な値またはEOF。
- 7.21.6.2 paragraph10：入力変換結果が格納先で表現できない場合の未定義動作。単にscanfの戻り値を確認するだけで数値の範囲超過まで安全になるとはしない。
- 7.21.7.2：fgetsの読み取り上限、改行の保存、NUL終端、EOF／読み取り失敗。
- 7.22.1.4 paragraphs2–8：strtolの10進変換、endptr、変換なし、範囲超過時のERANGE。

試し割りの停止条件は、合成数の因数対の少なくとも一方が平方根以下であることから直接確認。2と3を除く素因数の6による剰余は1または5。`i <= num / i` は正の整数で乗算をしない等価な停止条件となる。ループ変数は平方根付近までしか増えず、`i + 2` / `i += 6` はCの最小保証int範囲でも収まる。printerの `n - 2` はn>=2の経路だけで評価し、加算前の終了で最大値を超えない。

`verify_batch_019.py` は各版についてC17の完全プログラムと関数用harnessをO2およびO0+UBSanで別々にコンパイルする。素数表0..50000は独立したエラトステネスの篩で生成し、負数・INT_MAX・平方数・固定シードの大きな値はPython整数の試し割りで照合する。入力検証ではINT_MAXを解析するだけのharnessを使い、巨大な全列挙はしない。列挙は小さな範囲と負数について実出力を照合する。
