## 修正の根拠

原文と英訳は、上限を含む一覧を返す `primes_up_to(max: usize)` として整理した。上限2未満は空、上限2では候補3を処理しない。候補を処理する前に範囲を確認し、最後の奇数加算も残り距離が2以上の場合だけ行う。

見つかった素数は昇順に保持される。合成数の素因数には平方根以下のものがあり、それはすでに小さな候補を処理した段階で一覧に入っている。したがって割り切れなければ `p > n / p` で打ち切れる。元の「一覧の全素数で割る」実装は1000で正しいが、平方根より大きい試し割りは不要である。これを誤分類と呼ばない。

`n <= max` の経路では `max - n` が表現範囲内であり、残りが2以上のときだけ増分を加えるため、`n + 2` はmax以下に収まる。この境界の論証と、実行した有限範囲の検査を区別する。usizeMAXまで実際に列挙する検査はしない。
