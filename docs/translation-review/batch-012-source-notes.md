## 実際に確認・修正した点

- 旧PKCE例は28個の32ビット乱数の各下位8ビットしか残さず、56文字でも最大224ビット分になる。同じ下位8ビットで上位24ビットだけを変えると同じverifierになることを、日本語・英語それぞれのコードから再現した。S256のハッシュ処理自体はRFC 7636付録Bのベクトルに一致した。
- 修正版は32バイトをすべて符号化し、43文字のverifierを生成。S256方式を明示し、許される文字と長さを確認する。秘密のverifierをログに出す実行例を除き、呼び出し側が試行ごとに保持・破棄する範囲を説明した。
- 旧Python例の `jwt.decode()` は、署名が正しければ `exp`・`iat`・`sub` の欠落、nonceの欠落・不一致などを受け入れた。`sub` 欠落時は後続の表示でKeyErrorになるため、これをログイン成功の実証と誤って数えていない。一般JWTデコーダーの挙動とOIDC全体の検証は区別した。
- 修正版は、RS256・非暗号化・単一文字列audience・nonce送信済みという構成に限定し、必須項目の存在、型、nonce、azpを検査。JWKS取得・試行の照合・state・nonceの一回限りの使用・追加の認証要件は呼び出し側またはOIDCライブラリの責任として明示した。
- 認証結果とアクセス権、公開／機密クライアント、クライアントクレデンシャルの用途、ROPCとImplicitの勧告の強さ、JWSとJWE、署名と暗号化、発行者内のsubject識別子、期限と全体の有効性、任意の更新トークンと失効の条件を訂正した。
- 元の公開日時・slug・画像を維持し、変更日と説明に即したタイトル・descriptionを更新した。暗号技術とXSS/CSRFへの内部参照は各言語版へ結び付けた。
