# 強調記号が文字として表示される記事の修正

`前**CDN (x)**後` のように括弧・句読点と日本語などが隣接すると、CommonMark の強調区切りの条件を満たさず、`**` が本文に残る場合があります。

`scripts/fix_emphasis.py` は全言語の `content/post/*/index*.md` を調べ、問題のある単純な強調だけを `<strong>CDN (x)</strong>` に置換します。文章への空白追加や、サイト全体のMarkdown設定変更は行いません。既存の `unsafe: true` 設定を利用します。

```powershell
# 検出・検証のみ（記事は変更しない）
python scripts/fix_emphasis.py

# 検証に合格した箇所を一括修正
python scripts/fix_emphasis.py --write

# テスト
python -m unittest discover -s scripts -p test_fix_emphasis.py -v
```

レポートの既定出力先は `docs/emphasis-report.json` です。保存先は `--report` で指定できます。

## 表示を保護する方法

- 正常な強調、フロントマター、コード、Mermaid、数式、リンク・画像、見出し、引用、参照定義などは修正対象から除外します。
- HTMLやショートコードを含む記事、通貨と数式の区別が曖昧な記事、入れ子のMarkdownを含む強調は保守的に除外します。
- 実際にインストールされているHugoと現在の `markup` 設定を使い、一時的な最小サイトで記事本文の修正前後を変換します。HTML全体について、対象の文字列 `**…**` が `<strong>…</strong>` に変わる差分だけであることを完全一致で検証します。記事によって引用符の自動変換などに差が出る場合は、その箇所を修正しません。
- 検証用サイトにはテーマのレンダーフックを含めません。本文のMarkdown変換を比較する検証です。実サイトとの統合確認は別途 `hugo --renderToMemory` で行います。
- 元ファイルの改行・BOM・メタデータを維持し、変更対象以外のソースはそのまま保存します。書き込み前に元データを再確認し、並行編集を検知した場合は停止します。

安全に判定できないすべての表記を自動修正するものではありません。`skipped_render_mismatch` には、候補の一部または全部がHTML比較に合格しなかった記事を記録します。もともとHTMLなどの保護構文がある記事は、この一覧には含みません。再実行で既に修正した箇所が二重変換されることはありません。

内部リンク用スクリプトはHTMLを含む記事を保守的に除外するため、`<strong>` を追加した記事も今後の自動リンク追加対象から除外されます。既存の内部リンクは保持されます。
