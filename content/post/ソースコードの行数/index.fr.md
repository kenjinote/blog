# Nombre de Lignes de Code Source

Bonjour !

Aujourd'hui, j'aimerais vous parler d'un sujet un peu différent.

Le sujet est : "Dans quelle mesure le nombre de lignes de code source a-t-il augmenté par rapport au passé ?"

Par exemple, le logiciel de la navette spatiale était composé d'environ 420 000 lignes de code. Ce code a été développé selon un processus très rigoureux pour répondre aux normes de qualité élevées de la NASA. D'autre part, dans les grands projets de logiciels modernes, il n'est pas rare que le nombre de lignes de code dépasse des dizaines de millions. Par exemple, on dit que la base de code de Google atteint environ 2 milliards de lignes.

Comme nous pouvons le voir, l'échelle des logiciels a augmenté avec le temps.

Mais attendez une minute.

Une augmentation du nombre de lignes de code n'est pas nécessairement une mauvaise chose. Il est naturel que le code augmente pour ajouter de nouvelles fonctionnalités et répondre aux besoins des utilisateurs. Cependant, à mesure que le code augmente, le risque de bugs augmente également. En fait, certaines recherches montrent que les projets open source ont tendance à voir leur taux de bugs augmenter lorsqu'ils dépassent le million de lignes.

Cependant, tous les projets n'augmentent pas leur code de la même manière.

Par exemple, le noyau Linux comptait environ 200 000 lignes dans la version 1.0 en 1994, mais a atteint environ 20 millions de lignes dans la version 4.2 en 2015. Cette augmentation est due à la nécessité de prendre en charge l'évolution du matériel et l'ajout de nouvelles fonctionnalités.

Par conséquent, le nombre de lignes de code source varie considérablement en fonction de la taille et de l'objectif du projet, ainsi que du contexte de l'époque.

L'augmentation des lignes de code en elle-même n'est pas un problème, mais elle nécessite une gestion appropriée pour maintenir la qualité et la maintenabilité. Il est important de comprendre les risques associés à la croissance du code et de prendre les mesures appropriées.

Enfin, je pense qu'il est important de ne pas trop se focaliser sur les lignes de code, mais plutôt de privilégier l'objectif et la qualité du projet.
