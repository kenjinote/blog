# Número de líneas de código fuente

¡Hola!

Hoy quiero hablar sobre un tema un poco inusual.

Se trata de "¿Cuánto han aumentado las líneas de código fuente en comparación con el pasado?".

Por ejemplo, el software del transbordador espacial constaba de unas 420.000 líneas de código. Este código fue desarrollado bajo un proceso muy estricto para cumplir con los altos estándares de calidad de la NASA. Por otro lado, en los proyectos de software a gran escala modernos, no es raro que el número de líneas de código supere varias decenas de millones. Por ejemplo, se dice que la base de código de Google alcanza unos 2 mil millones de líneas.

De esta manera, la escala del software ha ido creciendo con el tiempo.

Pero, esperen un momento.

El aumento en el número de líneas de código no es necesariamente algo malo. Para agregar nuevas funciones o responder a las necesidades de los usuarios, es natural que el código crezca. Sin embargo, a medida que aumenta el código, también lo hace el riesgo de errores (bugs). De hecho, una investigación muestra que cuando un proyecto de código abierto supera el millón de líneas, la tasa de aparición de errores tiende a aumentar.

Dicho esto, no todos los proyectos aumentan su código de la misma manera.

Por ejemplo, el kernel de Linux tenía unas 200.000 líneas en la versión 1.0 de 1994, pero aumentó a unas 20 millones de líneas en la versión 4.2 de 2015. Este aumento se debe a la necesidad de adaptarse a la evolución del hardware y agregar nuevas funciones.

Por lo tanto, el número de líneas de código fuente varía mucho según la escala, el propósito y el contexto histórico del proyecto.

El aumento en el número de líneas de código en sí mismo no es un problema, pero para mantener la calidad y la capacidad de mantenimiento, es necesaria una gestión adecuada. Es importante comprender los riesgos asociados con el aumento del código y tomar las medidas adecuadas.

Por último, creo que es importante no obsesionarse demasiado con el número de líneas de código, sino centrarse en el propósito y la calidad del proyecto.
