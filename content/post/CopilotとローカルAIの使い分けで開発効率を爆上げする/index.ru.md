# [Copilot или локальный ИИ? Выбор по данным и измерениям](https://kenji.blog/p/hybrid-ai-development-workflow/)

Ассистенты программирования варьируются от автодополнения в IDE до агентских изменений. Не считайте облако более мощным, а локальную обработку — автоматически более безопасной. Проверяйте, какие данные передаются, какие условия действуют, качество на ваших задачах, задержку и эксплуатационные расходы.

Руководство основано на официальной документации, проверенной 23 ноября 2026 года. Продукты, модели, настройки и политики меняются — перед внедрением заново проверьте ссылки и правила организации.

## У облачного ИИ и локального вывода разные пути данных

В зависимости от модели и функции IDE облачные службы, такие как GitHub Copilot, могут отправлять сервису запросы, фрагменты кода и релевантный контекст репозитория. Согласно текущей политике GitHub, данные взаимодействия в индивидуальных планах Copilot могут использоваться для обучения и улучшения моделей; отказаться можно в личных настройках. GitHub также заявляет, что данные клиентов Copilot Business и Enterprise не используются для обучения без разрешения клиента. Проверьте план, хостинг модели, функцию и настройки администратора.

- [Политики GitHub Copilot для индивидуальных подписчиков](https://docs.github.com/en/copilot/how-tos/manage-your-account/manage-policies)
- [Хостинг моделей и обработка данных GitHub Copilot](https://docs.github.com/en/copilot/reference/ai-models/model-hosting)

При локальном выводе модель работает на устройстве, и входные данные могут оставаться там. Но одна лишь локальная модель не гарантирует полностью автономную работу. Проверьте телеметрию и синхронизацию расширения, внешние инструменты и сетевой трафик при загрузке моделей. В руководстве Continue описана предварительная подготовка расширения и модели и отключение анонимной телеметрии для автономного режима.

- [Использование Continue без интернета](https://docs.continue.dev/guides/running-continue-without-internet)

У Ollama есть локальный API `http://localhost:11434` и размещенный в облаке API `https://ollama.com/api`, для которого нужен ключ. Ollama не означает, что вывод обязательно локальный. Проверьте настроенный endpoint. Если открываете локальный сервер для сети, отдельно настройте контроль доступа.

- [Адреса и использование API Ollama](https://docs.ollama.com/api/introduction)

## Выбирайте путь с учетом задачи и классификации данных

Начните с классификации данных и политики использования ИИ в организации. Определите, какой код, журналы, документы и учетные данные разрешено выводить за пределы одобренной среды. Не помещайте секреты в запросы — даже локальные: заменяйте их тестовыми значениями. Для облака проверьте использование для обучения по плану, хранение, мониторинг злоупотреблений, регион, администрирование и передачу хосту модели.

- Обычное автодополнение, комментарии или черновики тестов: проверьте качество, задержку, интеграцию с IDE и отправляемые данные; используйте одобренную облачную функцию или небольшую локальную модель.
- Резюме или изменение внутреннего кода: проверьте объем ввода, обоснование результатов, договор и хранение; используйте одобренное организацией облако или контролируемую локальную среду.
- Конфиденциальный или регулируемый код: проверьте внешнюю передачу, журналы, сетевой периметр и аудит; требуется изолированная локальная среда, одобренная организацией.
- Масштабное проектирование или сложная отладка: оцените качество, контекст, права инструментов и стоимость; используйте подходящее облако или модель с внутренним хостингом.
- Работа без интернета: заранее загрузите нужные файлы и проверьте трафик расширения, обновления и исправления безопасности; протестируйте автономную конфигурацию.

Это не рейтинг производительности, а отправная точка для отбора вариантов по правилам организации и оценкам задач.

## Измеряйте качество, задержку и цену на одних задачах

Создайте небольшой тестовый набор с критериями успеха, примерами ошибок и методом оценки. Давайте кандидатам одинаковый код и инструкции, фиксируйте ID модели, расширение, дату и настройки. Сравнивайте точность, прохождение тестов, соответствие текущему дизайну, безопасные отказы и время исправлений. Повторяйте испытания, так как результаты меняются. Важный код должен проверять разработчик и запускать его тесты.

Измеряйте время до первого результата отдельно от полного времени. Учитывайте облачное потребление, подписку, повторы и ревью, а также покупку, электричество и обслуживание локального оборудования. Скорость и качество локальной модели зависят от размера, квантования, контекста, GPU/памяти и настроек IDE. Проверяйте на своем устройстве, а не только по числу параметров или оценке VRAM.

## Краткая инструкция по запуску локальной модели

Установите Ollama, проверьте лицензию, размер загрузки и возможности модели в каталоге, затем загрузите точную метку:

```sh
ollama pull <model-name:tag>
```

Текущий формат Continue позволяет зарегистрировать Ollama так. Замените `<MODEL_ID>` точным ID загруженной модели из `ollama list`.

```yaml
name: Local coding model
version: 0.0.1
schema: v1
models:
  - name: Local model
    provider: ollama
    model: <MODEL_ID>
    apiBase: http://localhost:11434
    roles:
      - chat
```

Вызов инструментов, изображения и контекст зависят от модели. Проверяйте работу, даже если IDE распознала функции автоматически. Начинайте с минимальных прав. Агентам, меняющим файлы или запускающим shell-команды, нужны проверка и подтверждение человека. Учитывайте prompt injection во внешнем коде.

- [API Ollama](https://docs.ollama.com/api/introduction)
- [Настройка Ollama в Continue](https://docs.continue.dev/customize/model-providers/top-level/ollama)
- [Библиотека моделей Ollama](https://ollama.com/library)

## Начните с малого и переоценивайте при изменениях

Выберите задачу с низким риском и сравните одобренную облачную функцию с локальной моделью на одном наборе тестов. Оцените качество, время исправления, задержку, стоимость и адресатов данных, затем согласуйте правила команды для разных задач. При изменении модели, плана, расширения или договора проверьте политику и оценки повторно.

Безопасность определяется не только выбором между облаком и локальным запуском. Понимайте путь обработки, минимизируйте входные данные и проверяйте все в одобренной среде.
