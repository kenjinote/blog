# [Copilot या स्थानीय AI? डेटा सीमाओं और माप से निर्णय लें](https://kenji.blog/p/hybrid-ai-development-workflow/)

कोडिंग सहायक IDE में सुझाव से लेकर एजेंट द्वारा बदलाव तक कई रूपों में हैं। यह न मानें कि क्लाउड अधिक सक्षम और स्थानीय अपने-आप अधिक सुरक्षित है। भेजे जाने वाले डेटा, लागू शर्तें, वास्तविक कार्य गुणवत्ता, विलंब और संचालन लागत जाँचें।

यह मार्गदर्शिका 23 नवंबर 2026 को जाँचे गए आधिकारिक दस्तावेज़ों पर आधारित है। उत्पाद, मॉडल, सेटिंग और नीतियाँ बदलती हैं; अपनाने से पहले लिंक और संगठन के नियम फिर जाँचें।

## क्लाउड AI और स्थानीय inference के डेटा मार्ग अलग हैं

GitHub Copilot जैसी क्लाउड सुविधाएँ मॉडल और IDE सुविधा के अनुसार prompt, कोड अंश और उपयोगी repository संदर्भ सेवा को भेज सकती हैं। GitHub की वर्तमान नीति के अनुसार व्यक्तिगत Copilot योजनाओं के interaction data का उपयोग मॉडल प्रशिक्षण और सुधार के लिए हो सकता है; व्यक्तिगत सेटिंग में इससे बाहर निकलने का विकल्प है। GitHub यह भी कहता है कि ग्राहक की अनुमति के बिना Copilot Business और Enterprise का ग्राहक डेटा प्रशिक्षण में उपयोग नहीं होगा। अपनी योजना, मॉडल होस्ट, सुविधा और प्रशासक सेटिंग जाँचें।

- [व्यक्तिगत ग्राहकों के लिए GitHub Copilot नीतियाँ](https://docs.github.com/en/copilot/how-tos/manage-your-account/manage-policies)
- [GitHub Copilot मॉडल होस्टिंग और डेटा प्रबंधन](https://docs.github.com/en/copilot/reference/ai-models/model-hosting)

स्थानीय inference में मॉडल आपके उपकरण पर चलता है और इनपुट वहीं रह सकते हैं। फिर भी स्थानीय मॉडल चुनना पूर्णतः ऑफलाइन व्यवस्था की गारंटी नहीं है। एक्सटेंशन टेलीमेट्री, सिंक, बाहरी टूल और मॉडल डाउनलोड के दौरान नेटवर्क ट्रैफ़िक जाँचें। Continue की ऑफलाइन मार्गदर्शिका पहले से एक्सटेंशन व मॉडल तैयार करने और अनाम टेलीमेट्री बंद करने के चरण बताती है।

- [इंटरनेट के बिना Continue चलाएँ](https://docs.continue.dev/guides/running-continue-without-internet)

Ollama में `http://localhost:11434` पर स्थानीय API और API कुंजी वाला होस्टेड क्लाउड API `https://ollama.com/api` दोनों उपलब्ध हैं। Ollama का उपयोग अपने-आप स्थानीय inference नहीं है। कॉन्फ़िगर किया गया endpoint जाँचें। स्थानीय सर्वर को नेटवर्क पर उपलब्ध कराने पर अलग से access control बनाएँ।

- [Ollama API के endpoint और उपयोग](https://docs.ollama.com/api/introduction)

## कार्य और डेटा वर्गीकरण के आधार पर मार्ग चुनें

संगठन की डेटा वर्गीकरण और AI नीति से शुरू करें। तय करें कि कौन-सा कोड, लॉग, डिज़ाइन और credentials अनुमोदित वातावरण से बाहर जा सकते हैं। स्थानीय या क्लाउड किसी भी मॉडल को prompt में secrets न दें; उनकी जगह परीक्षण मान रखें। क्लाउड के लिए योजना अनुसार प्रशिक्षण उपयोग, retention, दुरुपयोग निगरानी, क्षेत्र, प्रशासक नियंत्रण और मॉडल होस्ट को डेटा भेजना भी जाँचें।

- नियमित completion, टिप्पणी या परीक्षण मसौदा: गुणवत्ता, विलंब, IDE एकीकरण और भेजे गए डेटा देखें; अनुमोदित क्लाउड सुविधा या छोटा स्थानीय मॉडल।
- आंतरिक कोड का सार या संपादन: इनपुट सीमा, परिणामों की समीक्षा, अनुबंध और retention देखें; संगठन द्वारा अनुमोदित क्लाउड या नियंत्रित स्थानीय वातावरण।
- गोपनीय या विनियमित कोड: बाहरी प्रेषण, लॉग, नेटवर्क सीमा और ऑडिट जाँचें; नीति पूरी करने वाला पृथक और अनुमोदित स्थानीय वातावरण।
- बड़े डिज़ाइन या कठिन debugging: मूल्यांकन गुणवत्ता, संदर्भ सीमा, टूल अनुमति और लागत जाँचें; आवश्यकता के अनुरूप क्लाउड या आंतरिक मॉडल।
- इंटरनेट-विहीन काम: डाउनलोड पहले तैयार करें; extension ट्रैफ़िक, अपडेट और सुरक्षा सुधार जाँचें; ऑफलाइन व्यवस्था सत्यापित करें।

यह प्रदर्शन रैंकिंग नहीं, बल्कि संगठन के नियमों और कार्य परीक्षणों से विकल्प छाँटने की शुरुआत है।

## समान कार्यों पर गुणवत्ता, विलंब और लागत मापें

सफलता मानदंड, विफलता उदाहरण और स्कोरिंग विधि वाला छोटा परीक्षण सेट बनाएँ। सभी उम्मीदवारों को समान कोड और निर्देश दें तथा मॉडल ID, extension, तारीख और सेटिंग दर्ज करें। सटीकता, परीक्षण पास होना, मौजूदा डिज़ाइन से मेल, उचित इनकार और सुधार में लगा समय तुलना करें। परिणाम बदलते हैं, इसलिए कई बार चलाएँ। महत्वपूर्ण कोड की समीक्षा और परीक्षण डेवलपर करें।

पहले आउटपुट तक का समय और पूरा होने का समय अलग मापें। कुल लागत में क्लाउड उपयोग, सदस्यता, पुनः प्रयास और समीक्षा समय के साथ स्थानीय हार्डवेयर, बिजली और रखरखाव जोड़ें। स्थानीय गति और गुणवत्ता मॉडल आकार, quantization, context length, GPU/मेमोरी और IDE सेटिंग पर निर्भर हैं। केवल पैरामीटर संख्या या एक VRAM अनुमान से निर्णय न लें; अपने उपकरण पर जाँचें।

## स्थानीय मॉडल आज़माने के न्यूनतम चरण

Ollama इंस्टॉल करें। मॉडल कैटलॉग में लाइसेंस, डाउनलोड आकार और क्षमताएँ जाँचें, फिर सटीक tag प्राप्त करें:

```sh
ollama pull <model-name:tag>
```

Continue के वर्तमान विन्यास में Ollama को इस तरह दर्ज कर सकते हैं। `<MODEL_ID>` को `ollama list` में दिख रहे डाउनलोड किए मॉडल ID से बदलें।

```yaml
name: Local coding model
version: 0.0.1
schema: v1
models:
  - name: Local model
    provider: ollama
    model: <MODEL_ID>
    apiBase: http://localhost:11434
    roles:
      - chat
```

टूल कॉल, चित्र इनपुट और संदर्भ सीमा मॉडल के अनुसार बदलते हैं। IDE स्वतः पहचान ले, तब भी वास्तविक व्यवहार जाँचें। न्यूनतम अधिकार से शुरू करें। फ़ाइल बदलने या shell कमांड चलाने वाले एजेंट के लिए मानव समीक्षा और स्वीकृति अनिवार्य रखें। बाहरी स्रोत कोड में prompt injection का भी ध्यान रखें।

- [Ollama API](https://docs.ollama.com/api/introduction)
- [Continue में Ollama विन्यास](https://docs.continue.dev/customize/model-providers/top-level/ollama)
- [Ollama मॉडल लाइब्रेरी](https://ollama.com/library)

## छोटे काम से शुरू करें और बदलाव पर फिर मूल्यांकन करें

कम जोखिम वाला काम चुनें और उसी परीक्षण सेट पर अनुमोदित क्लाउड सुविधा तथा स्थानीय मॉडल की तुलना करें। गुणवत्ता, सुधार समय, विलंब, लागत और डेटा के गंतव्य देखें; फिर कार्य-विशिष्ट टीम नियम बनाएँ। मॉडल, योजना, एक्सटेंशन या अनुबंध बदलने पर नीति और परीक्षण फिर जाँचें।

सुरक्षा केवल क्लाउड या स्थानीय विकल्प से तय नहीं होती। डेटा प्रवाह समझें, इनपुट न्यूनतम रखें और अनुमोदित वातावरण में परीक्षण करें।
