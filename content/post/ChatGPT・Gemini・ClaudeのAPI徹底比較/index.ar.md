# [اختيار واجهات OpenAI وGemini وClaude البرمجية بناءً على القياس](https://kenji.blog/p/chatgpt-gemini-claude-api-comparison/)

تتيح OpenAI وGoogle Gemini وAnthropic Claude الذكاء الاصطناعي التوليدي عبر واجهات API. تتغير أسماء النماذج والميزات والتوافر والأسعار والشروط باستمرار. ولا تثبت قائمة قديمة أو نتيجة معيار واحد أن مزودًا بعينه هو الأفضل دائمًا.

تمت مراجعة هذا الدليل وفق المصادر الرسمية في 23 نوفمبر 2026، ويعرض طريقة قابلة للتكرار للاختيار. راجع الكتالوج والعقد الحاليين لكل مزود قبل التنفيذ.

## ميّز بين واجهات API ومنتجات المحادثة

إن ChatGPT وتطبيق Gemini وClaude.ai ليست المنتجات أو العقود نفسها التي تقدمها واجهات API. لا تستنتج من إعدادات المحادثة الاستهلاكية طريقة مصادقة API أو فوترتها أو حدودها أو مدة الاحتفاظ بالبيانات أو كيفية استخدامها. وقد يختلف معالج البيانات والشروط عند استخدام النموذج عبر مزود سحابي.

راجع كتالوجات [نماذج OpenAI](https://developers.openai.com/api/docs/models) و[نماذج Gemini](https://ai.google.dev/gemini-api/docs/models) و[نماذج Claude](https://platform.claude.com/docs/en/about-claude/models/overview). تحقق أيضًا من خطط الإيقاف ومعرّفات الإصدارات وحدود السياق ومدخلات الصور والصوت والفيديو واستدعاء الأدوات والتوافر لمشروعك ومنطقتك. يختلف الدعم حسب النموذج ونقطة النهاية.

## أنشئ تقييمًا خاصًا بالمهمة قبل اختيار الفائز

لا تضمن التصنيفات العامة الجودة مع بياناتك وتعليماتك وتكلفة أخطائك. أنشئ مجموعة تقييم من الاستخدام الفعلي، مع معايير نجاح وأمثلة إخفاق ممثلة. لا ترسل بيانات شخصية أو سرية قبل التحقق من الإذن والنظر في إخفاء الهوية.

1. حدّد المهمة والمدخلات والمخرجات المتوقعة بدقة.
2. استخدم المدخلات والتعليمات والأدوات وتنسيق المخرجات وإعدادات التوليد نفسها. سجّل معرّف النموذج وتاريخ الاختبار، ووضّح أي ميزة حصرية لمزود تؤثر في المقارنة.
3. قيّم الدقة الواقعية والالتزام بالأدلة والتنسيق والتعامل مع الطلبات التي يجب رفضها كلًا على حدة. اطلب مراجعة بشرية للمعايير المهمة وأضف فحوصًا آلية عند الحاجة.
4. أجرِ قياسات متعددة بحمل ومنطقة وإعداد بث متقاربة.
5. أطلق الاستخدام تدريجيًا وأعد التقييم عند تغيير النموذج أو التعليمات.

استخدم المعايير العامة لاختيار المرشحين مبدئيًا فقط. لا تقارن مباشرة نتائج مجموعات بيانات أو طرق تقييم أو إصدارات نماذج أو إعدادات استدلال مختلفة.

## قِس الجودة والكمون والتكلفة معًا

سجّل الجودة وزمن الاستجابة والتكلفة والتوافر على مجموعة التقييم نفسها.

- **الكمون:** قِس الزمن حتى أول رمز (TTFT) منفصلًا عن زمن الإكمال الكلي. سجّل الوسيط ومقياس الذيل البطيء مثل p95. راعِ الشبكة والانتظار وطول المدخلات والمخرجات والأدوات والتزامن.
- **التكلفة:** قدّر جميع العناصر القابلة للفوترة لكل مهمة، بما فيها المدخلات والمخرجات والتخزين المؤقت والصور والصوت والأدوات وإعادة المحاولة. يختلف عدد الرموز والأسعار باختلاف النموذج.
- **التشغيل:** تحقق من حدود الطلبات والمهل الزمنية وتكرار التنفيذ عند إعادة المحاولة والتوافر الإقليمي والمسار البديل عند الفشل. تعتمد الحدود على العقد والمشروع والنموذج.

تختلف شروط التخزين المؤقت للموجهات والمعالجة المجمعة حسب المزود والنموذج وواجهة API والمدخلات والاحتفاظ والسعر. لا تفترض أن الخصم دائم. راجع الأسعار الرسمية لدى [OpenAI](https://developers.openai.com/api/docs/pricing) و[Gemini](https://ai.google.dev/gemini-api/docs/pricing) و[Claude](https://platform.claude.com/docs/en/about-claude/pricing) ووثائق الميزات.

## قارن واجهات API ومجموعات SDK واستخدام الأدوات

تختلف الواجهات ومجموعات SDK وحالة المحادثة واستدعاء الأدوات وقيود JSON بين المزودين. قد تسهّل الواجهة المشتركة الانتقال، لكنها قد تخفي ميزات أو عناصر تحكم خاصة بمزود معين. تحقق من أدلة البدء الرسمية من أن واجهة API وSDK الحاليتين تلبيان احتياجاتك.

استدعاء الأداة لا يعني أن النموذج ينفذ الدالة بنفسه. يقترح النموذج الأداة والوسائط، بينما يجب على التطبيق التحقق منها والتصريح بها وتنفيذ الإجراء وإعادة النتيجة. تحقّق من الوسائط وطبّق أقل الصلاحيات واطلب موافقة بشرية على الآثار المهمة. لا يضمن تنسيق الإخراج المقيّد صحة المحتوى أو سلامته.

## اختر بين RAG والسياق الطويل باستخدام بياناتك

يبحث التوليد المعزز بالاسترجاع (RAG) عن مستندات ملائمة ويضيف مقتطفات مختارة إلى المدخلات. لا توجد طريقة أفضل دائمًا. قارن حداثة المستندات وجودة الاسترجاع وحجم المدخلات والحاجة إلى الأدلة والكمون والتكلفة والمعلومات المفقودة باستخدام بيانات ممثلة.

حد السياق هو الحد الأقصى، وليس ضمانًا لدقة متساوية حتى ذلك الحجم. اختبر استرجاع المعلومات من مواضع مختلفة في المدخل الطويل والاستدلال عبر المستندات. وإذا استخدمت التخزين المؤقت، فتحقق من شروط الأهلية وطريقة الاحتفاظ بالبيانات وحذفها.

## تحقق من حماية البيانات وشروط العقد

لا تعمم أن بيانات API لا تستخدم مطلقًا للتدريب أو لا تُحتفظ بها. تحقق من المنتج والخطة المجانية أو المدفوعة والميزة والعقد والمنطقة. على سبيل المثال، توضح Gemini Developer API شروطًا مختلفة لاستخدام البيانات للمستويين المجاني والمدفوع. ويميّز Anthropic بين Claude API المباشر والمسارات السحابية التي يكون فيها مزود السحابة معالج البيانات. كما توثق OpenAI ضوابط بيانات API وشروط الاحتفاظ بها.

- [ضوابط بيانات OpenAI API](https://developers.openai.com/api/docs/guides/your-data)
- [مراقبة إساءة الاستخدام واستخدام البيانات في Gemini](https://ai.google.dev/gemini-api/docs/usage-policies)
- [الاحتفاظ ببيانات Anthropic API](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention)

قبل الإنتاج، تحقق من مدة الاحتفاظ واستخدام البيانات لتحسين المنتجات ومراقبة إساءة الاستخدام والمراجعة البشرية والحذف ونطاق الاحتفاظ الصفري ومكان المعالجة والمعالجين الفرعيين ومتطلبات التدقيق. لا تضع مفاتيح API في تطبيقات العميل أو الشيفرة العامة.

## قارن قائمة قصيرة واتخذ القرار وفق القياسات

بدلًا من إعلان فائز مطلق، قيّم المرشحين لكل حالة استخدام. اختر النماذج من الكتالوجات الحالية، وقِس الجودة والكمون وتكلفة المهمة باستخدام البيانات نفسها، وأدخل متطلبات التشغيل ومعالجة البيانات في القرار. أعد التحقق من معرّفات النماذج والأسعار والشروط بانتظام.
