# [OpenAI・Gemini・Claude APIの選び方：実測と公式資料で比較する](https://kenji.blog/p/chatgpt-gemini-claude-api-comparison/)

OpenAI、GoogleのGemini、AnthropicのClaudeは、いずれもAPIから利用できる生成AIです。ただし、各社のモデル名、機能、提供地域、料金、利用条件は頻繁に変わります。過去のモデル名や一度のベンチマークから「常にこの会社が最良」と結論づけることはできません。

この記事では、2026年11月23日時点で、選定と比較を再現可能にする手順をまとめます。最新モデルと価格は変動するため、購入・実装時には必ず各社の公式カタログと契約条件を確認してください。

## まず「API」と「チャット製品」を分ける

ChatGPT、Geminiアプリ、Claude.aiは、各社のAPIと同じ製品・契約ではありません。APIの認証、課金、レート制限、保存期間、データ利用条件を、個人向けチャットの設定から推測しないでください。クラウド事業者経由のモデル提供も、データ処理者や利用条件が異なる場合があります。

最新のモデルID、機能、提供状況は各社のカタログで確認します。

- [OpenAI API models](https://developers.openai.com/api/docs/models)
- [Gemini Developer API models](https://ai.google.dev/gemini-api/docs/models)
- [Claude models](https://platform.claude.com/docs/en/about-claude/models/overview)

カタログ上の名称だけでなく、廃止予定、固定バージョンID、コンテキスト上限、画像・音声・動画入力、ツール呼び出し、構造化出力、地域・プロジェクトごとの利用可否を確認します。対応機能はモデルやAPIエンドポイントごとに違います。

## 勝者を決める前に、用途別の評価セットを作る

一般的なランキングは、自分のデータ、指示、失敗コストでの品質を保証しません。実際の用途から、成功条件と失敗例を含む評価セットを作ります。個人情報や秘密情報を含む実データは、送信許可と匿名化を確認してから使ってください。

1. **対象タスクを限定する**：例えば、問い合わせ分類、社内文書の回答、コード修正など、入力と期待する出力を定義します。
2. **同じ条件で候補を評価する**：同一の入力、システム指示、ツール、出力形式、生成設定を使い、モデルIDと実行日を記録します。各社固有の機能を使う比較は、その差を明記します。
3. **品質を基準表で採点する**：正確性、根拠への忠実さ、形式遵守、拒否すべき入力への対応を分けます。重要な項目は人が確認し、必要なら自動テストも併用します。
4. **複数回・本番相当の条件で測る**：モデル出力にはばらつきがあります。十分な件数、同程度の負荷と地域、ストリーミング有無をそろえて比較します。
5. **段階導入して回帰を監視する**：プロンプトやモデルを更新するたびに同じ評価を再実行し、重大な失敗を本番へ流さない仕組みを用意します。

公開ベンチマークは候補を絞る参考にとどめます。データセット、採点方法、モデル版、ツール使用、推論設定が異なるスコア同士を単純に比較しないでください。

## 品質・遅延・費用を同時に測る

モデル選択は、正答率だけの競争ではありません。少なくとも、品質、応答時間、費用、可用性を同じ評価セットで記録します。

- **応答時間**：リクエスト開始から最初の出力までの時間（TTFT）と、完了までの時間を分け、中央値と遅い側の値（例：p95）を記録します。ネットワーク、キュー、入力・出力長、ツール実行、同時実行数の影響も切り分けます。
- **費用**：入力、出力、キャッシュ、画像・音声、ツール、再試行など、実際に課金される要素を含めてタスク単位で見積もります。トークン数と単価はモデルごとに異なり、同じ文章でもトークナイザーが違えば数が一致しません。
- **運用性**：レート制限、タイムアウト、再試行時の重複実行、利用可能地域、障害時の代替経路を確認します。可用性や制限は契約・プロジェクト・モデルに依存します。

プロンプトキャッシュやバッチ処理は、使えるモデル、API、入力条件、保存期間、料金が各社で異なります。割引率を常に得られるものとみなさず、[OpenAIの料金](https://developers.openai.com/api/docs/pricing)、[Geminiの料金](https://ai.google.dev/gemini-api/docs/pricing)、[Claudeの料金](https://platform.claude.com/docs/en/about-claude/pricing)と各機能の公式説明で対象条件を確かめてください。

## API・SDK・ツール利用を比較する

各社は独自のAPI、SDK、会話状態、ツール呼び出し、JSON制約機能を提供しています。共通インターフェースを使うと移行しやすくなる一方、独自の機能や細かな制御が隠れることがあります。まず公式のクイックスタートで、必要な機能が現在のAPIとSDKで実装できるかを確認します。

ツール呼び出しは「モデルが関数を実行する」ことと同じではありません。モデルはツール名と引数を提案し、アプリケーション側が検証、認可、実行、結果の返却を担います。引数を検証し、最小権限を適用し、危険な副作用には人の承認を要求してください。出力形式の制約を指定できても、内容の事実性や安全性が保証されるわけではありません。

## RAGと長いコンテキストは実データで選ぶ

RAGは関連する文書を検索して必要な部分を入力に加える方式です。長いコンテキストに文書をまとめて渡す方式と、どちらが常に優れるということはありません。文書の更新頻度、検索品質、入力サイズ、回答に必要な根拠、遅延・費用、取りこぼしを含めた評価セットで比較します。

コンテキスト上限はモデルごとの最大値であり、そこまで与えれば同じ精度で扱えるという保証ではありません。長文の途中に置いた情報の取り出しや、複数文書をまたぐ推論もテストしてください。キャッシュが使える場合でも、対応条件とデータの保存・削除の扱いを確認します。

## データ保護と契約条件を確認する

「APIに送った情報は学習に使われない」「保存されない」と一括りにせず、利用する製品、無料・有料のプラン、機能、契約、地域ごとに確認します。例えばGemini Developer APIは無料枠と有料枠でデータ利用条件が異なると案内しています。AnthropicのAPI資料も、直接のClaude APIとクラウド事業者がデータ処理者となる経路を区別しています。OpenAIもAPIデータ制御と保存条件を公式に説明しています。

- [OpenAI API data controls](https://developers.openai.com/api/docs/guides/your-data)
- [Gemini API abuse monitoring and data use](https://ai.google.dev/gemini-api/docs/usage-policies)
- [Anthropic API data retention](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention)

本番投入前に、保存期間、学習・製品改善への利用、濫用監視、人による確認、削除手段、ゼロデータ保持の適用範囲、処理地域、委託先、監査要件を確認します。APIキーをクライアントアプリや公開コードへ埋め込まず、秘密情報として管理してください。最終的な判断は、適用される契約と組織の法務・セキュリティ基準に従います。

## 小さく比較し、測定結果で選ぶ

1社を無条件の勝者とするより、用途ごとに候補を評価する方が実用的です。最新カタログから候補モデルを選び、同一の評価データで品質・遅延・タスク単価を測定します。要件を満たす候補の中から、運用やデータ管理も含めて選び、モデルID・価格・利用条件を定期的に再確認してください。

この比較は2026年11月23日に公式資料を確認して更新しました。モデル・料金・ポリシーは変化するため、本文の説明を固定仕様として扱わず、各社のリンク先と契約条件を実装時に再確認してください。
